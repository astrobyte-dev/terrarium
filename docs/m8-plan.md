*Drafted 2026-07-09. Status: awaiting Corey's sign-off.*

## Where we are

M0–M7 done: headless core (234 tests), all five GUI screens live (Dashboard, Chat,

The one open wound: **`applyConfig` regenerates `openclaw.json` from the template**,

Everything else in M8 stacks on top of that fix, so it goes first.

## M8a — Config safety (top priority)

**Goal:** any core operation that rewrites `openclaw.json` preserves the user's
hand-tuning. Then re-enable the GUI Migrate/Release buttons.

**Approach — extend the carryover, don't fork the ops.** `applyConfig` already reads
the live file to carry over `meta`/`wizard` (apply.ts line 34). Widen that: treat the
**model domain as user-owned** and carry it from the live config into the regenerated
one. Template stays the authority on structure + secret mode; the user owns what the
model stack looks like.

Carried from live (user domain):
- `agents.defaults.model` — primary + fallbacks (live config wins over `brain.json`;
  the GUI already edits live in place, and the brain-store default has lied before)
- `agents.defaults.models` — per-model param overrides (e.g. GLM `enable_thinking: false`)
- `models.providers.<p>.models` — the hand-added model lists
- `models.providers.<p>.params` — e.g. ollama `num_ctx` bumps

Regenerated by template (app domain):
- secret placement per mode (`inline` vs `env-refs` SecretRefs) — **apiKey fields are
  always regenerated**, never carried, so a carried provider block can't smuggle a
  plaintext key into env-refs mode
- compaction, channels, gateway, plugins/skills, tools, commands

**Build (TDD, core):**
1. `config/user-tuning.ts` — pure `extractUserTuning(live)` → the four slots above;
   tolerant of missing keys. Unit tests first.
2. `buildOpenclawConfig` accepts the tuning in `TemplateCarryover`; applies it after
   the template build; apiKey/mode logic untouched. Precedence: live tuning >
   brain-store selection > template default.
3. Extend `round-trip.integration.test.ts`: hand-tune the fake live config (extra
   arliai models, swapped primary, `enable_thinking` override, num_ctx bump) →
   `migrate` → tuning survives AND no plaintext secret in file → `release` → tuning
   survives AND secrets inline again.
4. Re-enable NavRail Migrate/Release (drop `disabled`, restore honest confirm copy).
   Doctor stays read-only for now — repair becomes safe by this fix but re-enabling
   it is a separate, later decision.

**Acceptance:** the exact config that got nuked on 2026-07-09 survives a
migrate→release round trip byte-meaningfully intact (models, primary, params, ctx),
with only secret placement changing.

## M8b — Packaging: installable tray app

**Goal:** `Terrarium.exe` that runs independent of a dev terminal — which is what
makes Migrate a *persistent* mode (services live as children of a real tray app, not
of `npm run gui`).

- `electron-builder` in `packages/gui`, NSIS one-click target, asar, `tray.png` in
  extraResources. Core already bundles into main via electron-vite, ws stays a real dep.
- **Single-instance lock** (`app.requestSingleInstanceLock`) — two instances means a
  duplicate gateway, the documented poison loop. Non-negotiable before first install.
- Start-on-login toggle in the tray menu (`app.setLoginItemSettings`).
- Migration story: install → run tray app → Migrate (post-M8a, safe) → scheduled
  tasks stay disabled as the handoff completes. Tasks remain the documented fallback
  (Release hands back) until Corey trusts the tray.
- One-time documented admin step: `Disable-ScheduledTask 'OpenClaw Gateway'` from an
  elevated shell (that task's ACL denies non-elevated disable — known from M3).

**Acceptance:** install the .exe, quit the dev terminal, Migrate from the tray app,
close the window (hides to tray), Ella keeps answering on Telegram.

## M8c — Pic-gen in chat

**Goal:** photos render as image bubbles in the GUI chat, not Telegram-only.

- `pic_daemon` delivery abstraction: today it's hard-wired to Telegram
  `sendPhoto`/`sendMediaGroup`. v1 = deliver to **both**: keep Telegram delivery,
  additionally drop a JSON manifest (photo paths + session key) into
  `%LOCALAPPDATA%\Terrarium\inbox\`.
- GUI main watches the inbox → pushes an image `chat:message` to the renderer.
- ChatScreen image bubbles; images served via a registered `terrarium://` protocol
  in main (scoped to the output dirs) rather than loosening CSP to `file:`.
- Detailed design pass before build — this touches the proven daemon (backups +
  `py_compile`, same as the M3 patches).
